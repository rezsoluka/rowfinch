# Safety and privacy

Rowfinch is beta software. Queries you run can permanently change or delete database data. Review queries and generated scripts, keep appropriate backups, and use suitable database permissions. Generated SQL and AI suggestions require review. Exports and clipboard contents can include sensitive information; protect them accordingly.

The app presents this guidance on the first normal launch. Acknowledgement is a local preference, not permission to send database information to an AI service. It can be reviewed anytime through **About / Privacy**. Demo launches skip the first-launch dialog.

## Local storage

- Connection profiles in `connections.json` contain target/account settings and preferences, never SQL passwords or tokens. The configuration directory is `$XDG_CONFIG_HOME/rowfinch`, or `~/.config/rowfinch` when that variable is unset or relative.
- Connected SQL tabs retain the credentials needed for additional independent sessions privately in memory. Password fields are cleared after connection. Optional remembered SQL passwords use the `org.rowfinch.SqlPassword` desktop-keyring schema.
- ChatGPT account registrations and OAuth access, refresh, and ID tokens use the separate `org.rowfinch.ChatGptSession` desktop-keyring schema. They are not written to connection profiles, command-line arguments, application logs, or browser storage. The stable installation host identifier and notice preferences are stored in `settings.json` with owner-only permissions.
- SQL files and exports are written only to destinations you choose. Results, assistant questions, and answers remain in application memory unless you explicitly save, export, or copy them. Conversation history stays in the assistant window's memory unless you choose Save chat. Chat files are unencrypted and may contain sensitive SQL, schema and query results.
- Removing or purging the package leaves profiles, preferences, keyring entries, documents, and exports in place. **Forget saved password** removes SQL password entries for a profile. Assistant **Sign out** clears the selected account's local tokens and attempts to revoke its renewable session; registration metadata is retained for later sign-in. Unconfirmed remote revocation is reported, with a link to manage access in ChatGPT settings.

## Network requests

Database operations communicate with the configured SQL server. Microsoft Entra authentication uses Microsoft's identity services. Rowfinch has no application analytics or telemetry; database and identity providers handle their own requests under their policies.

Using the assistant's sign-in, model selection, or question features communicates with OpenAI. Existing ChatGPT conversations are not imported. Editor SQL, live schema access and result sharing are off by default. Connection notes you explicitly save are reloaded for that connection and included in the request preview when Include connection notes is checked. Sharing editor SQL, already-loaded schema, or a sample of displayed rows requires choosing the corresponding option. The question/context snapshot is visible before Send, and is sent with Rowfinch's SQL-assistance instructions. Separately enabled database capabilities can fetch and share additional metadata and approved query results during that question; these are shown in the Database access activity view. Follow-ups also include earlier completed messages, selected context and approved database results from this chat; these can be reviewed in Context under Earlier messages and shared data. Turning sharing off does not remove data already sent in earlier messages; New chat clears that history. Requests do not include password fields or database connection credentials automatically. SQL itself can contain secrets or personal data, so review the preview before sharing it.

Assistant requests use the Responses API with `store: false`; this is an API request setting, not a promise that a provider retains no data. Applicable OpenAI terms, account settings, and data policies govern processing. Eligible usage consumes the user's ChatGPT plan or credits and is subject to account/workspace limits. The user can review Rowfinch's access and usage in ChatGPT settings.

Database access is off by default and is never persisted as a grant. Enabling schema inspection permits live metadata reads of objects visible to the chosen database identity, including objects not expanded or displayed by the browser's current filters. Enabling queries opens an independent session using the chosen connected tab's authentication; it requires a dedicated read-only identity and checks effective permissions before enabling and before every query. Rowfinch does not create users or change database grants. Restricted SELECT syntax is an additional guard; a database administrator must provision appropriate SELECT permissions on approved objects or schemas. Broad writer, owner, execute or administrative identities are refused for query access.

Every assistant query presents its SQL, purpose, destination, and sharing limits for approval before execution. Approval also permits sharing the bounded result with OpenAI as part of this question. Declining blocks further queries for that question. Limits are 100 rows, 100 columns, 15 seconds, 2000 text characters or 1500 binary bytes per cell, and 24,000 characters per tool response. Metadata lists/columns are limited to 100 items; requests can be narrowed by name. Query data can be sensitive even when read-only. Activity and results are kept in memory in the assistant window. Choosing Save chat writes completed conversation/tool history and bounded results to your chosen file; the activity log itself is not saved. Each message can make at most eight database calls. Completed questions, answers, opaque model state and database tool/results history are retained in memory and sent with follow-ups in the same chat. Cancelled or failed exchanges are excluded from follow-up context. Chats are bounded to 20 completed exchanges and approximately 1,000,000 serialized input characters; the last completed answer can still be read when this limit is reached.

**Connection notes:** Context lets you explicitly save business descriptions for an exact server/database/user/authentication target. These notes live separately from chat history in `assistant-contexts.json`, stored unencrypted with owner-only permissions. SQL passwords, OAuth tokens and access grants are not added. Notes can themselves contain sensitive information; avoid including credentials. They reload for future chats and remain after New chat. Checked Include connection notes appends the visible notes to new request previews and sends them only when you choose Send. Unchecking stops new attachments without removing snapshots already shared in chat history. Opening a saved chat turns this option off until you opt in again. Clear notes and Save notes to delete the current target's saved text. Removing the app does not automatically delete this file.

**Saved chats:** Save chat explicitly writes a local `.rowfinch-chat.json` file containing completed questions/answers, shared context and bounded tool results, opaque model state for continuation, the draft, model ID, the local ChatGPT account registration ID, and nonsecret database/server/user display details. Credentials, tokens, connection strings, active sessions and access grants are not included automatically. User-entered SQL/messages or shared results can themselves contain secrets. Files are unencrypted; local saves use owner-only permissions and replace files atomically. Protect these files and open only chats you trust. No automatic chat history is maintained.

Open chat validates the format and restores a local conversation without sending its content or running saved tool calls. You can view it without signing in. Sending a follow-up shares the restored history with OpenAI and requires the original saved ChatGPT account registration. Database access is always off on opening; to fetch fresh data while retaining the chat you must explicitly enable the original database/server/user again. Each new query still requires approval. Opening another file asks before replacing an existing conversation or draft. Invalid files leave the current chat intact. New chat and closing the assistant clear memory; existing saved files remain until you delete them yourself.

New chat clears messages, shared snapshots and the activity view while retaining any enabled database access. Changing accounts or database connections/access clears the conversation to keep contexts separate. Closing the assistant cancels pending work and clears chat history. Disabling access cancels pending work and closes the independent session. Disconnecting/closing the chosen database tab, changing ChatGPT accounts, or closing the assistant also revokes access. The original query tab's session and transactions are independent. SQL-policy rejections execute nothing and return bounded validation feedback to OpenAI so the assistant can revise its SQL within the existing call limit; each accepted query still requires fresh approval. Complete requested SQL can be opened for manual review even after a rejected query or failed answer. Local variables remain blocked; reading @@DATEFIRST is allowed for date-boundary calculations. Data-changing SQL is never executed through the assistant. Opening other suggestions creates an unsaved SQL document for review; running those documents requires the user to choose Run. Failed or interrupted responses are marked incomplete.
